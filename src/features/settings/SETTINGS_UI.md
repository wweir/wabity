# Settings UI Rules

## Visual language

- 设置页和 launcher 共用冷静、专业、平和的中性色外观语言。
- Frame、导航、表单和卡片优先复用全局 token，不继续堆 frosted glass 风格。
- 透明窗口策略下，设置页只保留极小透明安全边；frame 背景和 overlay 必须跟随全局 surface token，不能写死浅色 frosted glass。
- 编辑卡片、空态、安装指引、内联代码和按钮都必须跟随全局 surface / text token。
- 模型页里的模型名下拉浮层、展开 / 刷新按钮和“多模态”能力卡也属于同一套 surface / border token。
- 所有自定义按钮、导航项和 jump item 都先清掉原生 `appearance`，再应用 token，避免深色主题重新冒出浅色系统按钮皮肤。
- Focus ring、active / hover / disabled 状态使用语义 token；不要靠白色 inset 高光、统一降透明度或遗留浅色常量适配 dark 模式。

## Frame and layout

- 设置页窗口宽高按当前显示器可用区域做上限裁剪，默认目标规格为 `1080 x 720`。
- 表单内容始终在页内单滚动区滚动。
- 设置页不跟随内容无限抬高或拉宽窗口。
- 窄窗口优先退让布局，不继续压缩内容。
- 浏览器预览和非桌面壳场景下，settings frame 宽度优先跟随 `window.innerWidth`，不能被 `screen.availWidth` 或共享最小宽度错误钉死。
- 左侧导航列保持窄宽度，把可用宽度让给右侧编辑区。
- 右侧配置卡、说明卡和长命令文本必须允许收缩换行，不能造成横向滚动条。
- 左侧导航只在真正窄窗口时才堆到主内容上方；`720px` 这类仍能容纳两列的宽度优先保留“左侧分组 / 右侧编辑”骨架。
- 右侧 quick jump 和 section toolbar 默认使用普通流内布局，不长期悬浮；小窗口中 sticky 浮块会侵占可视空间。

## Form and component defaults

- 默认优先使用输入框、下拉框、开关等原生表单控件。
- 没有明显信息分组或选择密度收益时，不引入额外卡片交互。
- 短字段型表单默认使用“左侧说明 / 右侧控件与帮助”的局部双列布局。
- `textarea`、目录列表、模型选择器和长说明块默认占满整行。
- 配置卡片内部字段列表允许按内容选择双列：知识库、模型、MCP 这类编辑卡里的多个短字段可以左右分布。
- Header、动作区、`textarea`、模型选择器、多行目录和长说明块自动跨满整行。
- 功能任务卡保持单列任务流，不参与共享双列。
- 快捷键录制卡和功能 / 知识库里的模型选择器需要更多横向可读空间：固定 settings 宽度下优先吃满整行，并比通用双列字段更早回退。
- 次级说明、安装提示和用途摘要优先平铺为普通区块；确实需要强调时才保留卡片层级。

## Actions and validation

- 需要显式保存的分组把保存、恢复已保存版本、定位问题动作收敛到主编辑区入口。
- 分组标题和窗口头部不承载保存语义。
- 输入密集分组优先使用紧凑状态 / 操作条，避免首屏再叠独立大卡。
- 功能、知识库和扩展页可以在表单前展示只读依赖健康摘要。
- 依赖健康摘要只说明跨页依赖风险和运行时回退，不承载保存、修复或校验定位动作。
- MCP 必填字段和 `KEY=VALUE` 文本格式即时校验。
- 字段级错误必须直接绑定到对应控件，通过 `aria-invalid` / `aria-describedby` 暴露给辅助技术。
- 不要只在分组底部堆总错误列表。

## General page UI

- 通用页不复用配置卡通用双列模板。
- 通知、外观这类线性设置保持单列顺排，避免打散依赖关系。
- 快捷键录制使用显式按钮 + 状态文案，不伪装成只读输入框。
- 快捷键录制必须支持键盘触发、录制态反馈，并把字段名程序化绑定给按钮本身。
- 桌面宽度下，快捷键项默认使用“左侧说明 / 右侧录制按钮”的双列布局；容器变窄时回退上下堆叠。

## Features page UI

- 功能页按“翻译配置 / 文档问答配置 / 截图识别”三个任务卡组织。
- 默认单列顺排，避免在当前 settings 宽度里把任务卡压成狭窄工作台。
- 顶部展示翻译、文档问答和 OCR 的依赖健康摘要。
- 每张任务卡只保留单层编辑容器；顶部放标题、状态和一句说明。
- 底部动作收敛成“单一主保存 + quiet 次级恢复操作”。
- 提示词编辑默认折叠，只先展示“使用默认 / 自定义 / 为空待恢复”的摘要状态；需要改提示词时再展开 textarea。
- OCR 配置放在翻译和文档问答之后；只有 provider 选中 `llm_ocr` 时才显示模型选择器，切走其它 provider 时仅隐藏，不主动清空草稿。

## Model page UI

- 没有 LLM 条目时显示单列 onboarding，不提前展示完整编辑工作台。
- 有条目后，宽窗口使用“目录 / 编辑”双栏；窄窗口回退为“目录在前、编辑在后”的单列流。
- 有条目时目录和编辑区已在首屏并列展示，不再显示 quick jump。
- 目录容器暴露 `radiogroup`，条目卡暴露 `radio`，键盘方向键可切换条目。
- 每个目录条目只展示名称、关键用途徽章、协议 / 模型和一行压缩后的接入摘要。
- 当前编辑状态条保持单层紧凑结构：条目名、保存状态、定位问题 / 恢复 / 删除 / 保存动作在同一入口。
- 模板外链和模型目录按钮使用轻量字段内辅助动作语法，不退回一排粗按钮。
- 模型列表按纵向单选目录展示；新增和删除动作从模型目录中分离。
- 右侧编辑区外层卡片保留稳定内边距；状态条和“连接信息 / 模型与用途”分段只在内边距内用分隔线组织。
- “使用模板”“调用方式”“模型来源”是显式模式切换，不是普通填空字段。
- 模型名优先是可手填 `combobox`；远端目录是辅助 `listbox` 候选面板。
- 候选面板在当前字段内占位并自身滚动，不能依赖越出编辑卡片的绝对定位。
- 从输入框方向键或右侧按钮打开候选面板时，焦点进入当前候选或首项；关闭或选中后回到输入控件或触发按钮。
- 筛选框和刷新按钮不能放进 `listbox` 选项语义内部。

## Knowledge page UI

- 知识库页面使用单列主流程。
- 顶部先给紧凑摘要面板，把保存状态并入“当前配置”头部。
- 顶部同时展示 Embedding 依赖健康摘要和索引重建提示。
- 操作条只承载定位、恢复、重建和保存动作。
- 有效边界、重建规则和最近一次手动重建结果并入“当前配置”。
- 下面顺排 Embedding 和目录配置，不做长篇左右分栏。
- 可编辑配置块把说明文案挂在对应字段标题下方；控件附近只保留必要操作按钮和错误。
- “当前配置”摘要卡保持单层容器：当前 Embedding 作为主信息，目录数 / 忽略数 / 校验问题作为扁平事实列表。
- 支持后缀和索引边界直接展示，不把扫描目录示例写成开发机路径；默认示例收敛为 `~/Documents`。

## Extensions page UI

- 扩展页顶部展示 Agent 单运行时说明，下方维护 MCP 配置。
- Agent 面板以说明为主：解释 session 由 Rust 后端通过 `pi::sdk` 创建，provider/model 优先复用文档问答模型，thinking/tools 等仍由 Pi SDK 自身配置决定。
- Agent 面板顶部展示文档问答模型复用状态、Pi SDK provider 桥接状态和 MCP 不自动注入说明。
- Agent 不展示外部 agent 安装卡片、命令模板、“选择 Agent”下拉或旧配置提示。
- MCP 的已配置服务目录使用顶部两列卡片。
- MCP 主区只在“当前服务”和“新建服务”两种模式里二选一，避免同时展示两个竞争主任务。
- 内置 MCP 固定展示独立能力面板，直接管理运行状态、总开关、地址和模块级开关。
- 自定义服务目录是顶部双列选择区，不占常驻侧栏；窄窗口回退成单列。
- 当前服务编辑区独占整行宽度，保证命令、地址、请求头和环境变量等长字段的可编辑空间。
- MCP 远程“请求头”是按需填写的高级字段；帮助文案通过 `aria-describedby` 绑定到 textarea，并说明“何时填写”“每行一个 `KEY=VALUE`”和例子 `Authorization=Bearer <token>`。
- 请求头 textarea 关闭拼写检查和自动大小写修正，避免宿主环境干扰技术字符串输入。
